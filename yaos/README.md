# FreeCast TV

Приём полного экрана iPhone на телевизоре YaOS / Android TV через AirPlay.
Русский интерфейс, управление пультом, без подписки, рекламы, аккаунта и лимита длительности сеанса.

Это самостоятельная сборка на основе [AirTV](https://github.com/0xb1ob/air-tv) и его ядра
[UxPlay](https://github.com/FDH2/UxPlay), а не модификация коммерческого AirScreen.
Исходный AirTV зафиксирован на `80e958d380e1c9cc609d037c439faec0826bc7b7`.
Изменения FreeCast TV распространяются вместе с исходниками по GPLv3.

## Установить на телевизор

Нужен телевизор на Android 7.0+ (API 24+) с возможностью устанавливать APK.
В сборку включены ARM64, ARMv7 и x86_64. Наличие YaOS само по себе не подтверждает
совместимость конкретного видеодекодера: проверка на вашем телевизоре обязательна.

1. Скопируйте `FreeCast-TV-0.1.0.apk` на USB-флешку.
2. На телевизоре откройте «Приложения» → «Файловый менеджер» → флешку.
3. Откройте APK и подтвердите установку. Если система попросит разрешить установку
   из этого источника, используйте штатный экран разрешений телевизора.
4. Запустите **FreeCast TV** в списке приложений.

Официальная инструкция YaOS по установке APK:
<https://alice.yandex.ru/support/ru/tv/apps/tv>.

## Обновления без флешки

После установки подписанного релиза кнопка «Обновление» на главном экране
проверяет GitHub Releases, скачивает новый APK прямо на телевизор и открывает
штатный установщик Android. На Android 8+ один раз разрешите FreeCast TV установку
приложений из этого источника. Каждую установку нужно подтвердить пультом;
приложение не устанавливает APK без разрешения пользователя.

Проверка новой версии запускается и при открытии FreeCast TV. Если релизов ещё нет,
кнопка сообщит об этом. APK из раздела Actions — тестовые сборки с временными
debug-ключами; они не подходят для обновления поверх подписанного релиза.
Для перехода с текущей debug-версии на подписанный релиз её придётся удалить и один раз
установить [FreeCast-TV-0.2.1.apk](https://github.com/ilyamordasov/airscreen/releases/download/v0.2.1/FreeCast-TV-0.2.1.apk), скачав APK на ТВ. Настройки и сопряжение
после удаления старой версии потребуется создать заново.

## Подключить iPhone

1. Подключите iPhone и телевизор к одной домашней сети. Телевизор может быть подключён
   к тому же маршрутизатору кабелем Ethernet.
2. Оставьте FreeCast TV открытым. Дождитесь состояния готовности.
3. На iPhone: **Пункт управления → Повтор экрана → FreeCast TV**.
4. После появления первого декодированного видеокадра экран ожидания скрывается.
5. Для завершения откройте «Повтор экрана» на iPhone и нажмите «Остановить повтор».

Приложение на iPhone не требуется. Официальные шаги Apple:
<https://support.apple.com/ru-ru/102661>.

## Пульт и настройки

### Передать видео из Safari без повторного QR

В FreeCast TV откройте «Трансляции» → «Передать ссылку с телефона». Для первой
настройки команды на iPhone запишите **адрес** и **ключ** с экрана ТВ. Ключ не
публикуйте: он разрешает открывать ссылки на вашем телевизоре. Телевизор и iPhone
должны быть в одной домашней сети, а FreeCast TV — запущен.

В приложении iOS «Команды» создайте команду «На FreeCast TV»:

1. В настройках команды включите «Показывать в меню „Поделиться“» и оставьте
   тип входных данных «URL».
2. Добавьте действие «Получить содержимое URL». В поле URL вставьте адрес с ТВ.
   Метод — **POST**, тело запроса — **Форма**.
3. Добавьте два поля формы: `url` = «Входные данные команды» и `token` = ключ с ТВ.
4. Добавьте действие «Показать результат» для ответа телевизора.

Теперь в Safari откройте видео и выберите «Поделиться» → «На FreeCast TV».
Команда передаст адрес текущей страницы, а ТВ попробует найти в ней прямой
HLS/MP4-поток и воспроизвести его своими средствами. Для потока, скрытого
через DRM, `blob:` или закрытые запросы, нажмите «Открыть страницу» на ТВ.
На странице кнопка «Указатель» включает курсор: стрелки двигают его, OK
нажимает, Back возвращает фокус кнопкам. После начала воспроизведения телефон
можно заблокировать. При смене адреса ТВ обновите URL команды.


- «Трансляции» открывает на ТВ плитки бесплатного эфира Матч ТВ и страницы
  матчей футбольного «Спартака». Отдельные матчи показывают бесплатно на Матч ТВ;
  Матч Премьер требует подписку. По информации провайдера его трансляции в
  браузере Smart TV не поддерживаются — используйте официальное приложение МАТЧ!.
- Если на ТВ установлен и запущен Ace Stream Engine, каталог также запрашивает
  его локальный поиск по «Спартак» и «Матч Премьер». Плитки P2P открываются в
  проигрывателе FreeCast TV через локальный HLS-поток движка, без Ace Player.
  Для воспроизведения внутри стороннего приложения Ace Stream может требовать
  опцию Proxy Server; без неё движок способен остановить поток примерно через
  пять минут. Поиск Ace Stream может не найти конкретный матч;
  поддержка обычных magnet-ссылок и TorrServer пока не добавлена.
- Каталог также загружает несколько опубликованных Content ID канала «Матч
  Премьер» с AceStreamID. Это сторонний источник: адреса могут устареть или не
  работать; приложение помечает их как непроверенные.
- Стрелки и OK выбирают кнопки. Фокус выделяется рамкой.
- «Запустить» / «Остановить» включают и выключают сетевой приёмник.
- «Настройки» меняют имя приёмника, 720p / 1080p и 30 / 60 fps. Сохранение
  перезапускает приёмник и прерывает текущую передачу.
- По умолчанию используется **1080p / 30 fps**. При рывках попробуйте **720p / 30 fps**.
- Во время видео OK или Back открывает панель управления.
- «Диагностика» показывает модель ТВ, Android API, ABI, IPv4, кодеки, число полученных
  пакетов и переданных на Surface кадров, а также последнюю ошибку. Эти сведения
  остаются на телевизоре; сервер сбора диагностики отсутствует.

Телевизор сохраняет пропорции iPhone. Чёрные поля по бокам вертикального экрана
нормальны. Выбранные разрешение и частота объявляются передающему устройству;
фактическое качество выбирает iOS с учётом сети и возможностей кодека.

## Если телевизор не виден

- Убедитесь, что FreeCast TV открыт и приём включён.
- Проверьте, что оба устройства находятся в одной локальной сети, а не в гостевом
  Wi-Fi с изоляцией клиентов.
- Откройте «Диагностика»: у телевизора должен быть локальный IP.
- Если VPN на iPhone блокирует доступ к локальной сети, измените его настройку
  локального доступа или временно отключите VPN для проверки.
- Нажмите «Остановить», затем «Запустить» и снова откройте «Повтор экрана» на iPhone.

Если есть соединение, но изображения нет, сделайте фото диагностики: наличие
видеопакетов при нулевом числе кадров указывает на другой этап, чем отсутствие
видеопакетов. Для проверки используйте домашний экран iPhone и собственное видео
из «Фото».

## Границы первой версии

- Реализован **полный повтор экрана с AAC-звуком**. Добавлен экспериментальный
  приём отдельного HLS-видео через кнопку AirPlay: ядро UxPlay поддерживает этот
  путь для YouTube. Для Safari и других приложений добавлен приём прямого
  медиаадреса из AirPlay `/play`; совместимость зависит от плеера сайта и пока
  не проверена на iPhone. ALAC декодируется программным декодером Apple;
  воспроизведение на физическом ТВ пока не проверено.
- Защищённое DRM-видео может давать чёрный экран; приложение не снимает защиту.
- Поддержка всех моделей YaOS и всех версий iOS не подтверждена. В `docs/VALIDATION.md`
  указано, что именно проверено для этой сборки.
- Сервер доступен устройствам в вашей локальной сети во время работы приложения;
  отдельного PIN в этой версии нет.
- Автозапуск после включения телевизора не добавлен. Откройте приложение с пульта.

## Сборка исходников

Зафиксированные инструменты:

| Компонент | Версия |
| --- | --- |
| JDK | 17 |
| Gradle | 8.7 (wrapper включён) |
| Android Gradle Plugin | 8.4.2 |
| Kotlin | 1.9.24 |
| compileSdk / targetSdk | 34 / 34 |
| minSdk | 24 |
| Android Build Tools | 34.0.0 |
| NDK | 26.1.10909125 |
| CMake | 3.22.1 |

Установите компоненты через SDK Manager в Android Studio. Задайте `ANDROID_HOME`
или укажите путь к SDK в `local.properties` (`sdk.dir=/absolute/path/to/sdk`).

```bash
./gradlew testDebugUnitTest assembleDebug
```

Тестовый APK: `app/build/outputs/apk/debug/FreeCast-TV-0.1.0.apk`.
Для подписанной версии:

```bash
export SIGNING_KEYSTORE=/absolute/path/to/freecast-tv.jks
export SIGNING_KEYSTORE_PASSWORD='your-password'
export SIGNING_KEY_ALIAS=freecast
./gradlew testReleaseUnitTest assembleRelease
```

`assembleRelease` требует собственный ключ и не подменяет его случайной debug-подписью.
Для установки обновления поверх выданного APK нужен тот же ключ, поэтому его
резервная копия передаётся отдельно от исходников. Не публикуйте приватный ключ.

Для публикации релиза через `.github/workflows/android-release.yml` создайте
постоянный keystore через Android Studio или интерактивно командой
`keytool -genkeypair -keystore freecast-release.jks -alias freecast -keyalg RSA -keysize 3072 -validity 10000`.
Храните keystore и пароли вне репозитория и сделайте резервную копию.
В GitHub → Settings → Secrets and variables → Actions задайте:

- `SIGNING_KEYSTORE_BASE64` — base64 содержимого keystore одним непрерывным текстом;
- `SIGNING_KEYSTORE_PASSWORD` — пароль keystore;
- `SIGNING_KEY_ALIAS` — имя ключа (например, `freecast`);
- `SIGNING_KEY_PASSWORD` — пароль ключа, если он отличается от пароля keystore.

Если у вас есть архив `FreeCast-TV-signing-key.zip` с исходным ключом, из каталога
`yaos` можно настроить все четыре секрета без вывода пароля в терминал:

```bash
gh auth login -h github.com
python3 tools/configure-github-signing.py /путь/к/FreeCast-TV-signing-key.zip
```

Скрипт сверяет сертификат с прежним подписанным APK. Архив содержит и ключ, и
пароль, поэтому храните его только как личную резервную копию, вне Git.

Релиз `v0.2.1` уже опубликован. Следующий тег, например `v0.2.2`, запускает тесты,
подписывает APK и публикует его в GitHub Releases. Следующие теги `vX.Y.Z` должны иметь
строго возрастающую версию; постоянный ключ менять нельзя.

Сборка не требует `.git`: C-исходники и статические библиотеки находятся в архиве.
Исходники статических зависимостей — `third_party_sources/`; контрольные суммы
зафиксированы в `third_party_sources/SOURCES.json`. Скрипт `tools/build-native-deps.sh`
может пересобрать их. Обычный запуск скрипта пропускает уже существующие библиотеки.
Для принудительной пересборки всех трёх ABI из включённых исходников:

```bash
ANDROID_NDK_ROOT=/absolute/path/to/android-ndk/26.1.10909125 \
FORCE_REBUILD=1 ./tools/build-native-deps.sh
```

Нужны Python 3, `make`, Perl и autotools. OpenSSL и libplist собираются для API 24.
Готовые библиотеки заранее не удаляются: новая библиотека заменяет прежнюю после
успешной компиляции. Исходная документация сохранена в `docs/UPSTREAM_README.md`.

## Проверки на реальном Android

```bash
./gradlew connectedDebugAndroidTest
```

Инструментальные проверки поднимают настоящий native RTSP-сервер, проверяют ответы
`OPTIONS` / `/info`, объявления mDNS и декодирование тестового H.264 в Android Surface.
Они не заменяют передачу с настоящего iPhone через ваш маршрутизатор.
